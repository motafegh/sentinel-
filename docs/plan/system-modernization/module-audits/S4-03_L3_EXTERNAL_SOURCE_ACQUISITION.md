## 2. Acquisition gates and bounded pilot

L3B0 first retrieve archive metadata/checksum and published license, inspect file list/size before downloading; if inaccessible, record failure and alternate author locator. For L3B1-B3 first acquire metadata and a maximum of 10 candidate source records per family (or fewer if scope/rights fail), not whole repositories by default. A record can be project-level, not necessarily one Solidity file. Budget 1 GiB downloaded across initial three-family source pilots and 5 GiB expanded scratch total; DIVE archive separate metadata-only until size reviewed. These are provisional engineering caps, not scientific targets. Use existing CPU tooling and cached compilers, at most three parallel compiler processes, per-case 30-second initial compile timeout; retain failures and dependencies rather than strip semantics. No credentials, live RPC, third-party install scripts, post-clone hooks, auto execution of untrusted projects or paid APIs. Inspect code/build instructions before any isolated later test. No execution of historical exploit scripts against live deployments; detect/patch research local-only.

Preflight record: exact upstream release/commit, archive bytes and checksum, license notice and per-file rights/attribution, source path, chain/address and deployment block where applicable, original source/file/component hashes, full imports/remappings and compiler/settings, annotation IDs/ranges, native class and evidence type, possible Sentinel mapping/abstention, related projects/incident/patch pairs and exposure role. Download to ignored staging, safe archive member validation, bounded extraction, no symlink escapes; record source-level availability and rejection reasons. If licensing or identity unresolved, metadata-only/quarantine, no redistribution. Pinned head is a reproducibility candidate, not proof of source availability/rights.

Compare to accepted V3 and all evaluation/RAG reservations using exact and normalized hash, bytecode where applicable, project family, template/near-duplicate groups and vulnerable/fixed pair identities. Check group bridges rather than simply remove duplicated files. Reserve prospective evaluation groups before tool/LLM review. Initial pilot outcome measures: acquisition and license-screen pass rate, source/build completeness, compile rate, class mapping ambiguity, independently reviewable candidate yield per group, duplicate/overlap count, source and review cost. Freeze samples and independent rubric before analysis, retain no-hit controls as unknown; no accepted label until owner approves versioned semantics/adjudication, role eligibility and immutable successor validation.

For RAG, retain source/version, claim IDs, attribution, citations and scope, distinguish report text from exact target evidence; no benchmark answers in the evaluation index. For project-level utility, begin read-only source investigation, measure finding grounding, coverage, false assertions, abstention, cost and analyst usefulness with a frozen rubric and project-level held-out split. No closed-world negatives from reports. Existing 8 GB GPU/64 GB RAM environment makes small local experiments preferable to broad code-model training; use CPU metadata filtering, chunked Parquet and lazy source retrieval. No model downloads/training in L3A.
